# Readable Windows Logging Policy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Author the three optional readable GPO policies with native registry/link operations and a narrowly scoped advanced-audit publisher, without importing upstream backups.

**Architecture:** `windows_logging_policy` executes once per domain on a designated host with protected local ownership/pending state. Native cmdlets and audit publication share one writer lock; existing unmanaged objects and unresolved pending state fail closed. AD/client evidence gates readiness, not static implementation.

**Tech Stack:** Ansible `ansible.windows.win_powershell`, Windows PowerShell 5.1, GroupPolicy/ActiveDirectory modules, MS-GPAC/MS-GPOL, UTF-8 CRLF CSV.

**Spec:** `docs/superpowers/specs/2026-10-22-portable-splunk-gpo-design.md` (user-approved; historical proposed-status text does not reopen scope).

## Global Constraints

- Follow `docs/instructions/ludus-authoring.md`: STATIC AND LIVE ONLY; no mocks, stateful fakes, simulated AD/client evidence or whole-repo validation.
- SDD selected; controller obtains plan confirmation before execution. No live AD reads/writes, endpoint probes, retirement execution, gpupdate, reboot or destructive cleanup authorized now.
- Preserve `role_gpo_deploy`, all collector roles/`splunk_forwarder`, source/range/blueprint files, preexisting staged `.opencode/skills/range-config/SKILL.md` and untracked `blueprints/detection-engineering/`.
- Role/directory `windows_logging_policy`; initial authoring target Windows Server 2022/PowerShell 5.1, recipients Server 2022/Windows 11 pending real-version evidence; no inferred installed Ludus identity.
- All three policies default disabled, names `Ludus-Logging`, `Ludus-CertEnroll`, `Ludus-DisableDefender`; explicit links default empty, enforced false. One unmistakable Defender-disabling-policy opt-in.
- No arbitrary importer, foreign PolicyServers tree/GUID, AD CS/template provisioning, source DACL adoption, default-domain-policy changes or generic transaction framework.
- Native settings/retirement implementation is allowed after plan confirmation; executing it requires separate authorization. No PowerShell 7 or effective Defender/issuance guarantee.

## Review Focus

1. CSV published before either version changes: pending must block rerun even when CSV matches desired and old AD/GPT versions agree (W3).
2. Lost/moved state, unmanaged name, GUID replacement or interrupted addition: fail closed rather than reconstruct ownership/adopt (W2–W3).
3. WinRM second hop, wrong domain/DC, RODC or denied SYSVOL: same-session preflight fails before mutation, never changes delegation (W2).
4. Native registry version change followed by audit update, malformed CSV or unrelated extension tuple/row: reread versions and preserve unrelated content (W3).
5. Check mode, empty links or disabled previously owned policy: read/plan only in check mode; intentional scoped retirement otherwise, never delete whole GPO/unknown settings (W3).

## Task W2: Designated-writer state and read-only native preflight

**Files — create:** `ansible/roles/windows_logging_policy/{defaults/main.yml,meta/main.yml,LICENSE,README.md,files/LoggingPolicyState.ps1,tests/test_policy_contract_static.py}`. These are helper/contract deliverables; full role entrypoint is assembled in W3.
**Public inputs:** `windows_logging_policy_domain/server: ''` discover joined domain/PDC; `owner_id: ludus-windows-logging-policy`; required `management_host`; `state_dir: C:\ProgramData\Ludus\WindowsLoggingPolicy`; `logging_enabled`, `enrollment_enabled`, `defender_disable_policy_enabled` all false. Prefix every abbreviated name here with `windows_logging_policy_`.
**Settings schema:** `names: {logging: Ludus-Logging, enrollment: Ludus-CertEnroll, defender: Ludus-DisableDefender}`; `links` has same keys, each `[]`, items `{target, enabled: true, enforced: false, order?: positive integer}`. `audit_subcategories` uses `{guid, success, failure}` for the exact 15 spec §5 GUIDs, both booleans true. `powershell: {module_logging_enabled: true, module_names: ['*'], script_block_logging_enabled: true, script_block_invocation_logging_enabled: true, transcription_enabled: true, transcription_invocation_header: true, transcription_directory: 'C:\Transcripts'}`. `enrollment: {renew_update_revoke: true, update_templates: true, offline_expiration_percent: 10, offline_expiration_store: MY}`. Controller-refined v1 interface: if `windows_logging_policy_enrollment_enabled` is true, both enrollment booleans must remain true; fail validation before writes for either false or any mixed combination. `defender: {disable_antispyware: true, disable_realtime_monitoring: true}` affects settings only after the single policy opt-in, not extra acknowledgments.
**Helper interface in `LoggingPolicyState.ps1`:** `Get-LoggingPolicyContext([hashtable] Configuration) -> hashtable` returns verified domain/DC identity, SYSVOL paths and read-only state/ownership view; `Enter-LoggingPolicyWriter([hashtable] Context,[bool] PlanOnly) -> IDisposable` supplies per-domain lock (read-only planning must not create lock/state files); `Write-LoggingPolicyState([hashtable] Context,[hashtable] State) -> void` atomically persists/flushes protected state or throws. W3 owns lock lifetime with `try/finally`; all errors are fatal.
**Shared shapes:** `Configuration` uses W2 public names with `windows_logging_policy_` stripped, plus `execution_inventory_host: string` and `desired_audit_csv: string` supplied by W3. `Context` keys are `domain_dns`, `domain_dn`, `domain_guid`, `dc`, `sysvol_root`, `state_path`, `writer_host`, `owner_id`, `state` (W1 schema). W3 adds `gpo_guid`, `gpo_dn`, `gpt_path` when calling the audit helper. Re-read ownership/state after acquiring the lock before mutation; an earlier read-only view is not authoritative against concurrent changes.

**Execution interface:** `tasks/main.yml` validates inventory-host/typed inputs then includes `policy.yml`. `ansible.windows.win_powershell` receives W2's structured `Configuration: hashtable`, including `execution_inventory_host` from `inventory_hostname` and `desired_audit_csv` from `audit.csv.j2`, not interpolated executable values.
