# dev1 Four-Workload Live Deployment Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `dev1` with four workload VMs and the repository-default router, then perform exactly one full initial deployment and determine installation outcome only from its terminal recap and range status.

**Architecture:** Keep GitLab, its Docker-executor runner plus native single-node K3s, Splunk, and the Windows Server 2022 primary DC on separate workload VMs. Add one fail-closed K3s prerequisite role and two bounded GitLab runner corrections, compose a secret-bearing range configuration only outside the repository, statically review only changed source/template files, then execute one authorized upload/verification/deploy/monitor cycle. K3s uses its embedded containerd while the GitLab runner retains the host `docker.io` daemon.

**Tech Stack:** Ludus 2.3.8, Ansible, Ubuntu 24.04, Windows Server 2022, GitLab CE/Runner Docker executor, K3s/Kubernetes, Helm 3, Splunk Enterprise/Universal Forwarder/OTel Collector.

**Spec:** `/tmp/opencode/dev1-live/recon-topology-v2.md`, superseding topology portions of `/tmp/opencode/dev1-live/recon-2026-10-22.md`.

## Review Focus

2. Docker is already running when K3s starts: preserve Docker and prove the K3s service is configured for embedded containerd, not cri-dockerd.
3. GitLab namespace is a user namespace rather than a group: resolve `/api/v4/namespaces/:url_encoded_full_path`, assert exact `full_path`, and use its namespace `id`; never substitute user ID.
4. Smoke CI is disabled: project/runner creation continues, but every repository-file lookup, desired-content fact, overwrite assertion, POST, and PUT is skipped.
5. Single-node scheduling/tool execution: role-internal bounded readiness checks establish a schedulable node and root-visible Helm/plugin/venv contract before the collector role starts.
